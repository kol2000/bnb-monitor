# Обновление, резервная копия и откат

Все команды выполняются на VM из `/home/bscbalance/bnb-monitor-git`.

Первое получение нового инструмента:

```bash
git pull --ff-only
sudo python3 manage.py update
```

Последующие обновления — одной командой:

```bash
sudo python3 manage.py update
```

Инструмент сначала сохраняет текущий Docker-образ отдельным тегом, `compose.yaml`, `.env` и весь том `/data` в `backups/<дата>/`. Для согласованной копии web и worker останавливаются на время архивации, затем запускаются. Если копия не создана, обновление не начинается. После получения кода собирается только web (worker использует тот же образ), затем проверяется здоровье обоих контейнеров.

При ошибке сборки или запуска автоматически возвращается сохранённый образ. База остаётся актуальной: откат старой базы мог бы потерять сведения об уже отправленных переводах и уведомлениях. Git checkout остаётся на полученной версии; запущенный образ указан в manifest резервной копии. Повторное обновление можно выполнить после исправления причины.

Отдельная копия:

```bash
sudo python3 manage.py backup
```

Ручной откат к сохранённому образу и конфигурации (подставьте имя каталога):

```bash
sudo python3 manage.py rollback backups/20261015T120000-abcdef
```

Откат проверяет контрольную сумму архива, сохраняет актуальный том данных и использует прежний compose с текущим .env. Архив базы автоматически не восстанавливается. Для восстановления после потери VM нужен отдельный перенос архива и проверка незавершённых операций по бирже/блокчейну до запуска обработчиков.

Копии содержат ключи, пароли и журналы: каталог имеет права 700, файлы — 600; он исключён из git и Docker build. Храните дополнительную защищённую копию вне VM. Не удаляйте Docker-теги `bnb-monitor-backup:*`, пока нужен откат. Копии автоматически не удаляются — следите за свободным местом.

## Шифрование новых копий

`manage.py backup/update` шифрует `data.tar.gz` и `.env` алгоритмом AES-256-GCM и удаляет временные незашифрованные файлы после успешной записи. Ключ `backup-encryption.key` создаётся рядом с `manage.py`, имеет права 600 и не попадает в git, Docker image или архив. Сохраните ключ отдельно от архивов: без него данные не расшифровать. Шифрование защищает вынесенную копию, но не от полного доступа к самой VM. Старые резервные копии автоматически не перешифровываются.

Для расшифровки скопируйте каталог резервной копии и ключ на доверенную машину. Команда ниже запускается из корня проекта на VM и создаёт **незашифрованные** файлы в выбранной копии (подставьте её полный путь):

```bash
sudo docker compose run --rm --no-deps --user 0 --entrypoint python \
  --volume "$PWD/backup_crypto.py:/backup_crypto.py:ro" \
  --volume "$PWD/backup-encryption.key:/backup-encryption.key:ro" \
  --volume "/полный/путь/к/копии:/backup" \
  web /backup_crypto.py decrypt /backup-encryption.key /backup
```

Это только расшифровка, без подмены рабочей базы и без запуска финансовых операций. При неверном ключе или повреждении архива расшифрованный файл не публикуется. Перед восстановлением базы нужно сверить незавершённые переводы и ордера: старое состояние не отражает операции, выполненные после копирования.
