# BNB Monitor 1.1

## Установка из GitHub

Репозиторий приватный. Для постоянного доступа с VM можно создать отдельный
SSH deploy key только для чтения (без Allow write access) в настройках репозитория.
После настройки SSH-доступа:

```bash
sudo apt update
sudo apt install -y git python3
git clone git@github.com:kol2000/bnb-monitor.git
cd bnb-monitor
python3 setup.py
sudo docker compose up -d --build
sudo docker compose ps
```

Обновление из папки проекта:

```bash
git pull --ff-only
sudo docker compose up -d --build
```

Если папка bnb-monitor уже существует после установки из архива, не клонируйте
поверх неё. Используйте другую папку для клона и перенесите прежний `.env`.
Compose использует фиксированное имя проекта и прежний Docker volume. Запускайте
только одну копию приложения. `setup.py` повторно для существующего `.env` не нужен.

## Google Таблицы: имена из A, адреса из B

Синхронизация доступна в веб-панели → Настройки → Google Таблицы.
В репозитории нет вашего ID таблицы, имён, адресов и ключей.
Укажите свою ссылку и точное имя вкладки (по умолчанию «Кошельки»).

Для автономной работы VM настройте сервисный аккаунт:

1. В https://console.cloud.google.com/ создайте или выберите проект.
2. Включите **Google Sheets API**.
3. В **IAM & Admin → Service Accounts** создайте сервисный аккаунт. Роли
   администратора проекта и domain-wide delegation не нужны.
4. На странице аккаунта в **Keys → Add key → Create new key → JSON** скачайте
   ключ. Храните его вне папки репозитория, например в отдельной закрытой папке
   на VM. Если политика Google запрещает ключи, не обходите её: потребуется OAuth.
5. Поделитесь нужной таблицей с `client_email` из ключа, роль **Читатель**.
   Доступ распространяется на файл целиком, не только на вкладку A:B. Если в файле
   есть другие чувствительные данные, используйте отдельную таблицу с A/B.
6. Перенесите JSON-ключ на VM через SFTP и из папки проекта выполните:

```bash
python3 configure_google.py /полный/путь/к/ключу.json
```

Скрипт копирует ключ в Docker volume с правами 600. Ключ не выводится на экран
и не передаётся аргументом процесса; используется stdin. Контейнер web должен
работать. В корневом репозитории JSON-файлы исключены из git и Docker build.
Приложение использует только readonly scope Google Sheets.

7. В веб-панели сохраните ссылку/ID, название вкладки, включите Google и нажмите
   «Синхронизировать сейчас». Дождитесь статуса с количеством импортированных адресов.

По умолчанию обновление раз в 300 секунд, после текущего цикла проверок. Новые
адреса добавляются, имена существующих обновляются; баланс, история и галочка
уведомлений сохраняются. Названия в старых событиях остаются историческими.
Имена ограничены 80 символами. Начальный баланс нового адреса не вызывает уведомления.
Список не удаляется при ошибке или пустой таблице. Удалённые строки не удаляют
кошельки из приложения. Если удалить адрес только в панели, он вернётся при
следующем импорте. Ручное переименование также заменится именем из таблицы.
Пустые строки пропускаются, неверные адреса учитываются в статусе; одинаковые
адреса с одинаковым именем объединяются. Один адрес с разными именами приводит
к ошибке всего импорта, без частичных изменений.

Ограничения: менее 5000 строк A:B и суммарно до 500 кошельков в приложении.
Если требуется больше — увеличьте лимиты только вместе с квотой RPC.
Ключ Google тоже входит в Docker volume: защищайте полные бэкапы VM.
Отдельная SQLite-копия ниже НЕ содержит файл ключа Google.

Официальные документы:
https://developers.google.com/workspace/guides/create-credentials
https://developers.google.com/workspace/sheets/api/scopes

Самостоятельно размещаемое приложение для Ubuntu Server / Docker на Proxmox.
Русская веб-панель, список BSC-адресов, баланс нативного BNB, история изменений,
уведомления в Telegram. Приватные ключи и seed-фразы НЕ используются.

## Что именно отслеживается

Это монитор изменения баланса, а не индексатор всех транзакций.
Один цикл получает завершённый блок `finalized` и читает `eth_getBalance`
для каждого адреса на одном номере блока. Chain ID обязательно 56.
Первое успешное чтение устанавливает базовый баланс без уведомления.
Следующие изменения записываются в SQLite; положительные изменения могут
отправляться в Telegram. Уменьшения видны в истории, но не отправляются.

Ограничения, важные до использования:

- Входящий перевод и расход между проверками могут взаимно компенсироваться.
  История показывает чистую разницу, а не сумму конкретного перевода. Хеша
  транзакции здесь нет. Для гарантированного отслеживания каждого поступления
  нужна другая архитектура с индексированием транзакций и внутренних переводов.
- Приложение отслеживает только нативный BNB, не WBNB, USDT или другие BEP-20.
- Баланс отображается на завершённом блоке, поэтому немного запаздывает.
  Если RPC не поддерживает finalized, ошибка видна в панели; автоматического
  перехода на неподтверждённые блоки нет.
- После простоя сравнивается последний сохранённый и текущий баланс. Полная
  история за период простоя не восстанавливается.
- Порог применяется к каждому обнаруженному приросту отдельно, без накопления.
- Уведомления доставляются с повторными попытками. При неопределённом исходе
  сетевого запроса или сбое между отправкой и записью в БД возможен дубль.
  В сообщении есть ID события, позволяющий его распознать.
- Начальный бесплатный RPC может иметь ограничения или перестать отвечать.
  В настройках можно указать до 5 HTTPS RPC, включая URL с API-ключом.
  При ошибке используются следующие адреса. Данные не обнуляются при сбое.
- До 500 адресов; массовое добавление до 200 за раз. Для большого числа
  кошельков понадобится подходящая квота RPC. Каждый кошелёк — отдельный запрос.
  Интервал 30 секунд отсчитывается после завершения цикла; фактический период
  больше и зависит от количества адресов и скорости RPC. Отправка Telegram
  выполняется после цикла и между циклами. Это не система мгновенного оповещения.
- Публичные адреса раскрываются выбранным RPC-провайдерам. Имена, адреса и баланс
  также передаются Telegram, если включены уведомления.

## Установка

Нужны установленный Docker и команда `docker compose`.
Перенесите архив в домашнюю папку пользователя VM через WinSCP (SFTP)
или `scp` с вашего компьютера. На Ubuntu:

```bash
sudo apt update
sudo apt install -y unzip python3
unzip bnb-monitor.zip
cd bnb-monitor
python3 setup.py
sudo docker compose up -d --build
sudo docker compose ps
```

`setup.py` спросит пароль панели (минимум 12 символов) и локальный IPv4 самой VM.
Адрес посмотрите командой `hostname -I` **до запуска Docker**, либо выберите
адрес сетевого интерфейса VM через `ip -4 addr`: не адрес docker0/172.x.
Рекомендуется закрепить этот адрес в DHCP роутера.
Пароль и секрет сессий сохраняются только локально в `.env` с правами 600.
Не отправляйте этот файл и токены в чат. Логин не нужен — только пароль.

Откройте `http://IP-ВАШЕЙ-VM:8080` из вашей локальной сети.
Docker скачивает базовый образ и зависимости при первой сборке; нужен интернет.
Если порт 8080 занят, измените PORT в `.env` и повторите `docker compose up -d`.
Без `.env` и пароля приложение не запустится.

Если получаете `permission denied` при `sudo docker compose`, проверьте
установку Docker. Все примеры используют sudo; добавлять пользователя в группу
docker необязательно. Группа docker фактически даёт административные права.

## Первый запуск

1. Войдите в панель по паролю.
2. Добавьте адреса, по одному на строку: `0x... Название`. Дубликаты пропускаются.
   При неверном адресе весь пакет отклоняется. Проверяется формат; регистр
   нормализуется. Проверка контрольной суммы EIP-55 в этой версии не выполняется.
3. Дождитесь появления балансов. Кнопка «Проверить сейчас» ставит запрос
   на ближайший цикл, но не запускает параллельные циклы.
4. В «Настройках» задайте Telegram, сохраните, отправьте тест.

История содержит последние 200 событий в панели; остальные остаются в БД.
Время показывается в часовом поясе браузера. Общий баланс — сумма последних
успешных значений, часть которых при ошибках может быть устаревшей.

## Подключение Telegram

1. В Telegram найдите официальный `@BotFather`, выполните `/newbot` и создайте
   отдельного бота для этого приложения. Полученный токен никому не отправляйте.
2. Откройте своего нового бота и отправьте `/start`.
3. Чтобы узнать ID именно своего чата, на VM в папке проекта выполните:

```bash
python3 telegram_chat.py
```

Скрипт спросит токен скрытым вводом, прочитает недавние сообщения вашего бота
через официальный Telegram API и покажет найденные чаты. Выберите свой личный
чат. Токен не записывается в файл. Не используйте токен чужого или общего
рабочего бота; активный webhook/другой обработчик может мешать getUpdates.

4. В панели введите токен и числовой Chat ID, включите Telegram и сохраните.
5. Нажмите «Отправить тестовое сообщение». Проверьте получение в своём чате.

Пустое поле токена при сохранении сохраняет старый токен. Для удаления есть
отдельная галочка. Токен не возвращается из API панели, но хранится в SQLite
в открытом виде. Защищайте VM и резервные копии.

Общее выключение Telegram отменяет сообщения в очереди, назад они не отправятся.
Очередь для удалённого кошелька отменяется. При выключенной галочке кошелька
ожидающие сообщения отменяются при следующей обработке очереди. Уже отправляемое
сообщение отменить нельзя. При смене Chat ID старая очередь не перенаправляется
новому получателю.

## Безопасность и сеть

- Предназначено для доверенной локальной сети и VPN. Порт привязывается к
  выбранному локальному IP VM, а не ко всем интерфейсам.
- НЕ пробрасывайте 8080 на роутере и не публикуйте приложение напрямую.
- HTTP не шифрует пароль, токен и сессию. В недоверенной сети используйте
  SSH-туннель или VPN; для постоянного HTTPS нужен отдельно настроенный reverse
  proxy, а в `.env` следует поставить `COOKIE_SECURE=1`.
- Веб-панель защищена паролем, CSRF, HttpOnly/SameSite cookie и ограничением
  попыток входа. Сессия длится 12 часов. Не является публичным multi-user сервисом.
- У Docker опубликованные порты могут обходить обычные правила UFW. Не считайте
  только UFW достаточной защитой: контролируйте доступ на Proxmox/роутере.
- Контейнеры работают не от root, без capabilities, с read-only корневой
  файловой системой; запись доступна в том данных и временную папку.
- Настройте автозапуск VM (Start at boot) в Proxmox и Docker:

```bash
sudo systemctl enable --now docker
```

Контейнеры перезапускаются при падении или перезагрузке (`unless-stopped`).
Статус unhealthy сам по себе не вызывает автоматический перезапуск Docker.
Это локальный монитор: при отключении всей VM он не сможет сообщить о собственном
отключении. Внешний контроль доступности в эту версию не входит.

## Обслуживание

```bash
# Статус двух контейнеров
sudo docker compose ps

# Последние логи (не публикуйте их без проверки на личные сведения)
sudo docker compose logs --tail=100

# Перезапустить
sudo docker compose restart

# Остановить без удаления данных
sudo docker compose down

# Запустить снова
sudo docker compose up -d
```

База, настройки и история находятся в Docker volume `bnb-monitor_monitor-data`.
НЕ выполняйте `docker compose down -v`: это удалит том с данными.
Логи ограничены 3 файлами по 5 МБ на контейнер. История в БД не обрезается
автоматически; следите за свободным местом на диске VM.

## Резервное копирование

Самый простой вариант — резервная копия всей VM средствами Proxmox.
Для отдельной согласованной SQLite-копии, из папки проекта:

```bash
sudo docker compose exec -T web python -c "import sqlite3; s=sqlite3.connect('/data/monitor.db'); d=sqlite3.connect('/tmp/monitor-backup.db'); s.backup(d); d.close(); s.close()"
sudo docker compose cp web:/tmp/monitor-backup.db ./monitor-backup.db
sudo chmod 600 monitor-backup.db
```

Сохраните также `.env` отдельно в защищённом месте. Копия базы содержит токен
Telegram и список кошельков. Не копируйте одну рабочую monitor.db на ходу:
SQLite использует WAL. Для восстановления предпочтительна полная копия VM;
ручное восстановление базы делайте только при остановленном worker.

## Смена пароля

Откройте `.env` на VM (`nano .env`) и замените ADMIN_PASSWORD (12+ символов).
Для завершения всех старых сессий замените также SECRET_KEY свежим случайным
значением: `python3 -c "import secrets; print(secrets.token_hex(32))"`.
Повторно примените конфигурацию: `sudo docker compose up -d --force-recreate`.
Не удаляйте Docker volume. Используйте одинарные кавычки вокруг пароля
в `.env`; сам пароль не должен содержать одинарную кавычку или перенос строки.

## Проверки разработчика

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
```

Тесты используют временную SQLite и подставные ответы RPC/Telegram, не реальные
кошельки и не реальные сообщения. Проверяются авторизация, CSRF, формат адресов,
точность до 1 wei, первый баланс, увеличение/уменьшение, отсутствие повторов,
сохранение после повторной инициализации, неверная сеть, резервный RPC,
отложенная доставка, скрытие токена и отмена очереди.
